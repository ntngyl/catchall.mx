DKIM checker

Finds the DKIM keys a domain publishes and checks each one is complete and long enough. Leave the selector empty and the common ones are tried for you.

Reads public DNS only. Lookups are not saved, and there is nothing to sign up for.

What a selector is

A domain can have many DKIM keys, one per sending service. Each is published under its own name, the selector, at selector._domainkey.yourdomain.com.

DNS has no way to list them, so a checker either needs the selector or has to guess. This one tries about thirty names the well-known mail services use, such as google, selector1 and k1.

Finding your selector

Open any email sent from the domain, choose "Show original" or "View source", and find the DKIM-Signature header. The value after s= is the selector, and d= is the domain it belongs to.

Common problems

The key was cut short

A 2048-bit key is longer than the 255 characters some DNS forms accept in one piece. If the end is missing, signatures fail. Providers handle long values differently; some split them for you, some need a different entry mode.

Quote marks inside the value

If your provider adds quotes itself and you paste a value that already has them, the quotes become part of the key and it stops working. Paste the value without any quote marks.

A 1024-bit key

It still verifies, but 2048 bits has been the standard for years. Keys shorter than 1024 bits are ignored by the large mailbox providers.

An empty p=

That is a revoked key. It is how a service says "do not trust signatures made with this selector any more".
